# Lesson and side-chat workflow

Use one shared upload set and two explicit chat roles. Send **Go** in the lesson
chat or **Side chat** in the supplemental chat. The generated instructions select
and retain that role; side-chat setup/report instructions are embedded in the
existing main instruction attachment rather than adding upload files.

The lesson chat teaches and assesses assigned objectives and returns its main
report. The side chat answers learner-initiated questions, clarification and
tangents; it does not advance lesson checkpoints or certify mastery. Direct
explanations and solutions are allowed when asked. Both roles use the same
source/context fidelity rules and favor useful UML with code and prose: class
for relationships, sequence for interactions, activity for control flow and
state for lifecycles. Use another representation when clearer. Tutor-authored
diagrams are explanations, not purported original source figures.

The supplemental template records exact lesson/context identifiers, a distinct
report_id, actual questions and explanations with source references, optional
actual learner responses, remaining questions, and exercise-related assistance
with before-answer/after-answer/unknown timing. Discussion is coverage only.
The planner preserves each report separately. Main and side reports may arrive
in either order; a late supplement is valid, and an unused side chat needs no
report. Side reports never close an outstanding lesson or import another formal
assessment. Matching pre-answer help or uncertain timing qualifies the affected
independence projection without rewriting archived observations. Post-answer
explanations alone do not downgrade an earlier independent answer. New tangents
inform planning; they do not silently expand the approved scope or workload.

Use the ordinary report import command for either report type. Inspect unmatched
assessment-help descriptions rather than assuming they apply to every question.
Use a fresh main-chat task for independent reassessment when useful. Preserve old
packets and reports unchanged; new instructions apply only to newly issued packets.

The human approved the interaction model on October 27, 2026. This is an accepted
design view of the manual handoff, not an automated chat integration. Its sequence
is illustrative; reporting order is flexible. [Diagram source](https://github.com/Matt-Salamone/invo-learn/blob/main/docs/design/lesson-side-chat-workflow.puml)
and [SVG preview](https://github.com/Matt-Salamone/invo-learn/blob/main/docs/design/lesson-side-chat-workflow.svg) describe these responsibilities.
